# Video Story

[![CI](https://github.com/jaromirsivic/video-story/actions/workflows/ci.yml/badge.svg)](https://github.com/jaromirsivic/video-story/actions/workflows/ci.yml)

Video Story is a plugin and skill for Claude Code, Codex and Cursor, and for Claude Desktop (and ChatGPT through a remote MCP server). While you work, you narrate what you are doing or what you want done. Video Story records your microphone, takes periodic screenshots of every connected screen and tracks the cursor; on Windows it also records your clicks, drags, scrolls and two-finger touchpad gestures together with the element under the mouse (a button, a field and its value, the paragraph you clicked into, the text you selected). The audio is transcribed offline with whisper.cpp - by default already while you record - and the agent receives a timed transcript together with the frames, so it can connect what you said with what was on screen and where the cursor was.

- Windows, Linux (X11) and macOS are supported. Windows and Linux were verified on real machines; macOS is verified on the GitHub Actions macOS runner (screens, cursor, recording, drawing capture) and still needs a hands-on check on a Mac with a microphone and a Retina display. The editor window is verified on Windows only.
- Hosts: used end to end with Claude Code on Windows (skills linked into `~/.claude/skills`). Codex and Cursor are set up from their documentation - `scripts/install-hosts` links the skills for each of the three hosts, and the repository installs as a plugin in each of them - but have not been exercised yet ([tests/manual/hosts.md](tests/manual/hosts.md) is the check); Claude Desktop and ChatGPT (MCP) are documented only. See [docs/installation.md](docs/installation.md).
- Recording and speech-to-text run locally: the transcription model is Whisper large-v3-turbo q5_0 (whisper.cpp, 548 MB, downloaded by `video-story setup`). What the agent then reads - the transcript, the texts you copied, the window titles and elements you clicked with their content (at most 4096 characters; password fields are never read) and the screenshots it opens - goes to the model the agent runs on, so it leaves the machine when that model is a remote one.
- The plugin UI and all messages are in English; the transcript keeps the language you spoke.

## How it works

1. Say "Start Video Story" to your agent. A small window stays on top of other windows.
2. Press **Record** and talk while you work. **Draw** (`Ctrl+Space` or `Ctrl+F1`) opens a drawing layer (rectangle `R` by default, ellipse `E`, line `L`, brush `B`, arrow `A` and an eraser `U` that removes every shape whose line it crosses; 9 colors on `1`-`9`; the right mouse button always draws an arrow; **Sketch** `S` swaps every screen for a white canvas and back, keeping the shapes; `Esc`, the cross on the toolbar or the Draw shortcut again leaves and clears everything drawn, `Ctrl+Z` undoes, also an eraser stroke, `Ctrl+Alt+C` clears; with Shift the rectangle is a square, the ellipse a circle, Shift held at the press or pressed during a brush stroke closes it and a line released with Shift held goes on as connected lines - each click starts the next, releasing Shift ends; with Ctrl the corners and ends of rectangles, ellipses, lines and arrows snap to a grid, **Drawing Grid** in Settings, 16 px by default, shown on the Sketch canvas only; the eraser removes whole groups, all connected lines or every piece of a line across screens; lines and arrows can cross screens) that is captured in the screenshots and described in each frame's sidecar JSON. **Keypoint** (`Ctrl+Alt+K`; it takes the place of Settings while recording) marks the current moment as important; the button counts down 3, 2, 1 before the next one. **Stop** is `Ctrl+Alt+S`. Two small icon buttons after Draw switch the window between the light and the dark theme (remembered) and **Hide to Tray**: the window hides behind the camera icon in the system tray, a balloon says that `Ctrl+Alt+S` still stops, and a left or right click on the icon brings the window back. The buttons name their shortcuts in brackets; on Windows the shortcuts work system-wide while recording (whichever program is in front), elsewhere while a Video Story window has the focus. Text you copy while recording (Ctrl+C) lands once, in the sidecar of the next frame, so the agent knows what "this text" was. Recording stops by itself after the configured time (2 hours by default) or when less than 1 GB is left on the disk of the recording folder (a message says so; Record does not start below 1 GB either). Either way the recording is saved and opens in the editor, exactly as after Stop. With **Mouse** switched on in Settings (the default; Windows for now) every click, double click, drag, scroll and two-finger touchpad gesture in other applications is recorded with the window, the element under the mouse and its content, so the timeline can say `CLICK left screen1 812,440 on button "Save" in "Settings" [notepad.exe]` instead of the agent having to look at a screenshot. The mouse hook and UI Automation run in two small helper processes, so the pointer never lags and a hanging application cannot block Video Story. A screen that cannot be captured for a while (lock screen, UAC prompt) simply has no frames for that time; the recording goes on. With **Live Transcription** in Settings set to **Light – low CPU use (recommended)** (the default) your speech is transcribed while you record, in a separate process at the lowest priority on a quarter of the CPUs, so your work, the screenshots and the mouse always come first; **Faster – more CPU** uses half of the CPUs at a slightly lowered priority, **Off – transcribe in the editor** leaves it all to the editor. The status line shows how far the transcript is behind (`text −0:25`); when frames start to drop, it takes half of its threads back by itself. The same model, decoding and audio mix as in the editor are used; the speech is cut into windows of up to 30 s that end in pauses, silence is skipped, and the language found in the first sentences stays for the whole recording.
3. Press **Stop** and choose **Video Editor** (the default), **Continue Recording** or **Discard Recording**. A stopped recording always goes through the editor, which opens at once: the recording is saved and the control window closes without waiting for the transcription. Recording continues until you decide.
4. The audio is transcribed on your CPU (Whisper large-v3-turbo, 5-bit quantised, automatic language detection) - while recording (see above) and then, for whatever is left, in the background of the editor, which continues the transcript in its language: a green arrow under the audio track shows how far the transcription got and the estimated time to the end (`transcribing (ETA: 2:05)`), subtitles appear as they are produced, and **Render Video** and **Process** stay disabled until it is complete. You can already watch the recording, move the crop handles, correct subtitles and type **Instructions** meanwhile: master instructions for the AI about the whole recording ("create an implementation plan from what I describe"), empty by default, stored as `instructions.txt`. Closing the editor early keeps what was transcribed; selecting the recording again continues where it stopped. Only the green **Process** button hands a recording to the agent: closing the editor, an editor that crashes, the auto stop or a recording window that dies hand over nothing (the recording is kept). **Auto process** presses Process five seconds after the transcription completes unless you click or type; it is never ticked when the editor opens and unticks itself when you select another recording. If the transcription fails, **Retry transcription** continues it from where it stopped. After Process the agent receives the instructions, `transcript.txt`, `transcript.json`, `manifest.json` (with the keypoints), the crop and `frames/` with one screenshot per screen and interval plus a sidecar JSON holding the cursor screen and position, the finished drawings visible at that moment (each with the time it was drawn; a shape still being dragged is only announced in `drawing_now`, its geometry follows once the mouse button is released) and the text copied just before it. Hallucinated subtitle credits ("Titulky vytvořil ...", "Subtitles by ...") are dropped from the transcript.
5. Recordings older than **Archive After** (30 days by default) are archived when the editor starts: every screen becomes one MP4 (with the audio tracks that are switched on in the editor) and every audio track is kept on its own as a small AAC file (`archive/audio.m4a`, `archive/computer.m4a`), whether it is switched on or not; then the frames and the WAV audio are deleted, the transcript stays. **Archive After** 0 (**Never** in Settings) switches this off; **Archive Video** in the editor still works. A recording you ask the editor for (`edit --session`, the one an agent waits on) is not archived by age in that run, and old recordings wait until the fresh recording an agent waits on is transcribed. An archive that fails before anything was deleted gives the recording back as an ordinary one (its row's tooltip says why); an automatic one is tried again at later editor starts, three failures at most. No recording is ever deleted automatically; **Settings** also offers **Open Folder** (recordings are deleted in the editor only). A new **Recording Folder** applies at once, also to the window that is already open.
6. If the recording window dies while recording (a crash, a power loss), nothing is lost: the next start of Video Story or of the editor finishes that recording from its frames and audio and lists it in the editor (without a transcript, which the editor then makes). It is not handed to the agent.

Recordings live in folders: `<recording_folder>/<folder>/<YYYYMMDD-HHMMSS>/`. The folder `default` always exists; a new recording goes to the *main* folder (`default` at first, chosen in the editor), and `<recording_folder>/folders.json` keeps the order of the folders, the main one, the pinned one and the collapsed ones.

Recording layout (`<recording_folder>/<folder>/<YYYYMMDD-HHMMSS>/`):

```text
manifest.json          screens, interval, format, audio, transcript summary, keypoints [{"index", "time_ms"}],
                       stop_reason (null | auto_stop | low_disk | capture_failed | recovered), frames.failed_grabs
audio/audio.wav        microphone, 16-bit PCM mono, device sample rate
audio/computer.wav     what the computer played (Windows), same format and rate
audio/tracks.json      the audio tracks switched on in the editor (when changed)
input/mouse.jsonl      the mouse (Windows, Mouse on): button, wheel, drag and gesture events, the
                       element under the mouse with its content (stored once by hash), window titles
agent/                 derived files the agent reads (timeline.txt, mouse.jsonl): written by the
                       `timeline` and `mouse` commands, rewritten by every call, safe to delete
crop.json              {"start_ms", "end_ms"} chosen in the editor (absent = whole recording)
instructions.txt       master instructions for the AI typed in the editor (absent = none)
transcript.txt         [HH:MM:SS.mmm --> HH:MM:SS.mmm] text
transcript.json        {"language": "cs", "complete": true, "segments": [{"start_ms", "end_ms", "text"}]}
                       (complete false + transcribed_ms while the editor is still transcribing)
frames/0_500_screen1.jpg   screenshot of screen1 at 500 ms (JPEG 70 % by default, PNG optional)
frames_info/0_500_screen1.json  sidecar of that frame: {"time_ms": 500, "screen": "screen1", "cursor": {"screen": "screen2", "x": 412, "y": 388},
                            "drawings": [{"id": 1, "tool": "rectangle", "color": "#FF0000", "screen": "screen1",
                                          "stroke_width": 4, "started_ms": 120, "finished_ms": 410, "background": "screen",
                                          "from": {"screen": "screen1", "x": 300, "y": 450},
                                          "to": {"screen": "screen1", "x": 750, "y": 675}}],
                            "drawing_now": null,  (while dragging: {"tool", "color", "screen", "started_ms"})
                            "zoom": [],
                            "background": "screen",  ("sketch": the white canvas; null while not drawing)
                            "grid": null,  (while Ctrl snaps shapes to the grid: its spacing in image pixels)
                            "clipboard": "text copied just before this frame (null in every other frame)"}
archive/                   only once archived: screen1.mp4 + screen1.srt + screen1.jpg (still from the
                           middle) per screen, every audio track as AAC 96 kb/s (audio.m4a = microphone,
                           computer.m4a = computer audio; the MP4 holds only the tracks switched on),
                           tracks.json (copy of audio/tracks.json, when there was one) and archive.json
                           (status queued | archiving | failed | cancelled | archived; failed = an
                           attempt failed with nothing deleted, cancelled = the user cancelled it
                           with nothing deleted and it is never archived automatically again -
                           either way the recording is an ordinary one); once archived,
                           audio/ and frames/ are gone,
                           frames_info/ and the transcript stay
```

## Editing and exporting

Say "Edit Video Story" and the **Video Story Editor** opens: a list of the stored recordings on the left, grouped by folder (each folder is an accordion: click its header to open or close it, remembered; the header shows the name, bold for the main folder where new recordings are saved, the number of videos, a pin - filled for the one folder pinned to the top; a click pins or unpins after a confirmation - and `⋯` with **Set as Main Folder**, **Move Up**, **Move Down**, **Archive All**, **Delete All Videos (N)** and **Delete Folder**; the folder-with-plus button right of "Recordings" creates a folder at the end and moves the selected videos into it; right-click a row for **Move Video to Folder...**; Shift/Ctrl select within one folder) (newest selected; each row shows a thumbnail, the date, the length and what was said, with one dot per screen, up to four, to switch the thumbnail of every row at once - each row shows the screen at the clicked position, or its last screen when it has fewer; hovering a dot names the screen and its size; move the mouse over a row's text to scrub through that recording, DaVinci Resolve style; right-click a row for **Open Folder Location**, **Render Video...**, **Archive Video**, **Cancel Archiving** and **Delete Video**, or Shift/Ctrl-select several rows for **Archive Videos (N)**, **Cancel Archiving (N)** and **Delete Videos (N)**; Cancel Archiving takes a waiting or running archive back while nothing was deleted yet, and that recording is never archived automatically again; Delete removes the recording folders for good after a confirmation, Archive turns every screen into an MP4 (with the audio tracks that are switched on) and a still from the middle, keeps every audio track as an AAC file, then deletes the frames and the WAV audio, one recording after another in the background - a label on the thumbnail says `TRANSCRIBING...`, `ARCHIVING...` or `RENDERING...` with the percentage, then `ARCHIVED`, which also blinks in the middle of the preview of an archived recording; an archived recording shows its stills and subtitles, can have its subtitles corrected, but cannot be processed or rendered any more), a preview with icon transport buttons and subtitles under it (always at least two lines tall so the picture does not jump, up to five lines, then scrolling) and, left of the transport, a mouse that follows the playhead (with Mouse recorded): the button pressed at that moment turns red, a turning wheel turns bright yellow together with the arrow of its direction; click it for the **Mouse** window, which stays open beside the editor and follows the playhead with everything recorded at that moment: five button boxes and four wheel arrows, the action in progress (click, double click, drag with its start, current point and end, scroll, gesture, modifiers, injected), the latest element under the mouse with its parents, bounds, drop target and content, the window, the latest copied text with when it was copied, and the mouse actions around the moment - and a timeline with one video track per screen plus the audio track (the toggle in its header stretches the waveform so that the loudest sound fills the track; the audio itself is unchanged; the microphone and speaker icons next to it switch the microphone and the computer's sound on and off - both are on by default and the track plays, shows, transcribes and renders their sum - and the pen icon deletes the narration and transcribes the current audio again from the start after a confirmation, also while a transcription is running) and the locked **narration** track under it: a box wherever a subtitle has words, showing the words once you zoom in. The search box under the list (Enter or the magnifier; the circular-arrow button next to it is Refresh) finds a word or phrase in the subtitles, ignoring case and diacritics: the shown recording first, then the others in the background; recordings with a match get a yellow frame, their matching narration boxes turn yellow and the phrase is bold and red in the subtitle under the preview. Zoom the timeline with -/+ (the playhead stays centred), drag the In/Out handles (or press `I`/`O`) to crop the start and the end (the crop is remembered per recording in `crop.json`; the handles snap to the green keypoint lines, marked by green arrows on the ruler, inserted while recording), click a screen track to choose what is exported. **Stop** returns to where **Play** was last pressed (a white arrow on the ruler). The bottom row holds **Auto process** (always unticked when the editor opens and after selecting another recording), the green **Process** (hands the cropped range and the instructions to the agent that opened the editor, all screens, which then acts only on that part of the recording; Auto process presses it by itself five seconds after the transcript is complete unless you click or type; while the agent waits for a recording that is still being transcribed, Process over another recording is refused), **Instructions** (master instructions for the AI about the whole recording; the templates **Draft Intent**, **Create Plan** and **Implement** fill in a formal brief, a plan or autonomous implementation), all at the right edge. **Render Video...** in a recording's right-click menu asks for the screen and the file (`Select File Name`) and renders the cropped range in the background into an MP4 (H.264 + AAC, constant 24 fps, screen resolution, cursor drawn in) with an SRT subtitle file next to it; the row shows `RENDERING...` with the percentage, one video renders at a time and **Cancel Rendering** on its row stops it; closing the editor while it renders asks first. The video recorded last (the one from the Stop dialog) has a light green background in the list whenever it is not selected. Hold the middle mouse button on the timeline to drag it sideways. The **Edit** button corrects the words of a subtitle (its times stay as whisper set them); the button above it switches between the light and the dark theme. A recording that is still being transcribed shows a green arrow under its audio track with the estimated time to the end and keeps Render Video and Process disabled until the transcript is complete. The mouse wheel zooms the preview up to 800 % around the cursor. `video-story export --session <id> --screen screen2 --start-ms 10000 --end-ms 60000` does the same without the window. The editor is verified on Windows; Linux and macOS follow.

## Quick start

```bash
uv sync
uv run video-story setup      # verifies FFmpeg and the whisper model, downloads them when missing
uv run video-story doctor     # environment report
uv run video-story run        # opens the control window and waits for the result
```

Settings (`config.json`), the model and a downloaded FFmpeg live in the state folder `~/.video-story`, apart from the code, so a plugin update keeps them; a development checkout with `config.json` in the repository keeps them in the repository, and `VIDEO_STORY_HOME` overrides both. `video-story config path` says which folder is used and why (details in [docs/installation.md](docs/installation.md#where-video-story-keeps-its-files)).

### Starting without an agent

Video Story also works on its own, without Claude Code or another agent: record, then watch, crop, correct subtitles and render the recording in the editor. Start it from the repository root with:

| | Recording window | Editor with the stored recordings |
| --- | --- | --- |
| Windows | double-click `start-video-story.bat` | `start-video-story.bat edit` |
| Linux, macOS | `./start-video-story.sh` | `./start-video-story.sh edit` |

The starters need only [uv](https://docs.astral.sh/uv/) (Windows: `winget install astral-sh.uv`). The first start creates the Python environment and, when they are missing, downloads FFmpeg and the Whisper model (`video-story setup`, about 550 MB). Then the window opens in its own process and the console closes; when something goes wrong (uv missing, a window already open) the console stays open with the reason. On macOS, Finder opens `.sh` files in an editor: run the starter from Terminal, or make a copy named `start-video-story.command` to double-click it. Without an agent, **Process** only closes the editor and keeps the recording.

Agents use `run --detach`, then `wait --session <id>` until the session is final. They read the user's instructions first, then `timeline --session <id>`: the cropped range as one text timeline (speech with the cursor position, finished drawings with their geometry and press/release times, removed shapes, copied text, cursor moves between screens, zoom, keypoints; written to the plain text file `timeline_file` - `<recording_dir>/agent/timeline.txt` or `--out <path>` - and repeated in the JSON only when it is short, so the output stays small for a recording of any length), so they decide from text which moments need a picture and fetch only those with `frames --session <id> --at <ms> --no-drawings`. See [skills/video-story/SKILL.md](skills/video-story/SKILL.md) for the agent workflow and [docs/installation.md](docs/installation.md) for setup and host registration (Claude Code, Codex, Cursor, Claude Desktop, ChatGPT).

## Development

```bash
uv run pytest tests/unit -q                                   # fast, offscreen
VIDEO_STORY_INTEGRATION=1 uv run pytest tests/integration -q  # real screens, microphone and model
uv run ruff check src tests && uv run ruff format src tests
```

The code is split into `core` (pure logic), `capture` (recording threads), `platform` (the only OS specific code), `transcribe`, `ui` (PySide6) and `host` (CLI, MCP server, session controller). What the application does is specified in [video-story-spec.md](video-story-spec.md) (in Czech, kept in step with the code); [implementation-plan.md](implementation-plan.md), [implementation-plan-editor.md](implementation-plan-editor.md), [implementation-plan-mouse.md](implementation-plan-mouse.md) and [implementation-plan-live-transcription.md](implementation-plan-live-transcription.md) are the design records.
